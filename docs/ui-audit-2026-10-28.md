## ส่วนที่ 1 สรุปผล

**ยังไม่พร้อม (Not yet)** มี blocker ที่เปิดอยู่ 6 เรื่อง

1. ช่อง input และ select บนมือถือหลายจุดเล็กกว่า 16px ทำให้ iOS Safari ซูมหน้าแล้วไม่ซูมกลับ (`f2.css:33`, `f2.css:59`, `styles.css:2161`)
2. ปุ่มที่กดได้จริงบนมือถือหลายตัวสูงแค่ 17 ถึง 32px (ปุ่มขอบเขต "ประเทศไทย" ใน F2 สูง 17px, ปุ่มปิด × 32px, breadcrumb F1 32px, ป้ายภาค 32px)
3. Modal ประวัติสถานีภัยพิบัติ (`app.js:3555`) เขียนเอง ไม่ย้าย focus เข้า ไม่ trap ไม่คืน focus เมื่อปิด
4. `outline: none` 13 จุดที่ใส่แค่เปลี่ยนสีขอบแทน focus ring ผู้ใช้คีย์บอร์ดมองไม่เห็นว่าอยู่ตรงไหน
5. Dock และมุมแผนที่ animate `left`, `right`, `bottom`, `width` ทุกครั้งที่เปิดปิดชีต (`styles.css:5049`) บนมือถือคือ layout ทุกเฟรม
6. ตัวหนังสือบนหน้าแผนที่ F4 ที่มองเห็น 23 จาก 24 ชิ้นเล็กกว่า 12px และ legend ลงไปถึง 8.5px

เรื่องที่ Peet ถามตรง ๆ ("กดยาก" และ "ที่แสดงข้อมูลน้อย") มีสาเหตุที่วัดได้ชัดและแก้ได้ด้วย CSS เกือบทั้งหมด ดูตารางถัดไปและข้อเสนอชีตโหมดขยายในส่วนที่ 3

1. ชีตทุกแบบมี 2 ระดับ: ปกติ (`top: 68px; bottom: 68px` เหมือนเดิม) และขยาย (`top: calc(env(safe-area-inset-top) + 8px); bottom: 8px`) ตอนขยายซ่อน `.map-header` และ `.department-dock` แบบที่ F2 ทำอยู่แล้ว และโชว์แถบ 44px "กลับไปแผนที่" ในชีต
2. ขีดจับบนชีต (`.panel-head::before`) เป็นปุ่มจริงที่สลับสองระดับ (`<button aria-label="ขยายข้อมูล" aria-expanded>`) ไม่ต้องเขียน gesture ก็ได้ผล ถ้าอยากได้ลากจริงค่อยทำทีหลังด้วย pointer events และ `touch-action: pan-x`
3. ขยายอัตโนมัติเมื่อผู้ใช้เลื่อนเนื้อหาในชีตลงเกิน 40px (ใช้ listener ที่ `f2.js:1273` มีอยู่แล้ว) และหดกลับเมื่อเลื่อนถึงบนสุด
4. header ในชีตหดเป็นแถวเดียว 48px เมื่อเลื่อน: F2 header 103px เหลือชื่อ + ปุ่มปิด, F4 header 115px + tabs 69px รวมเป็นแถบ tabs เลื่อนแนวนอนแถวเดียว 48px
5. รวมปุ่ม "ตัวกรอง" ของ F2 เข้าไปในแถว tabs เดียวกัน (ประหยัด 44px)

ผลที่คาดจากตัวเลขที่วัด: F2 พื้นที่อ่านจาก 485px เป็นประมาณ 700px (เพิ่ม 44%), F4 จาก 492 เป็นประมาณ 700px, ชีตจังหวัดจาก 578 เป็นประมาณ 740px, iPhone SE จากครึ่งจอเป็นเกือบเต็มจอ
ต้องตัดสินใจ: ยอมให้ dock หายตอนขยายหรือไม่ (ผู้ใช้ต้องกด "กลับไปแผนที่" ก่อนสลับฝ่าย) ผมแนะนำว่าใช่ เพราะตอนอ่านข้อมูลไม่ได้สลับฝ่ายบ่อย

**F. ฟอนต์** เลือกระหว่างตัด 800 ทิ้ง (แก้ 134 จุดเป็น 700 ด้วย sed คำสั่งเดียว) หรือ self-host Anuphan variable (ได้ 100 ถึง 800 จริง ไฟล์เดียว preload ได้) ผมแนะนำ self-host เพราะลำดับชั้นหัวข้อที่ออกแบบไว้พึ่งน้ำหนัก 800 จริง

**Z. z-index scale** ค่าที่เสนอในตาราง E ต้องให้ยืนยันลำดับ dock กับชีต (ตอนนี้ dock 32 อยู่ใต้ชีต 40 แต่ยังกดได้เพราะชีตไม่ทับ)

**R. reduced motion** patch R ตัดการเคลื่อนที่แต่เก็บ fade ไว้ ถ้าต้องการให้ reduce แปลว่าปิดทุกอย่างจริง ๆ ให้บอก

**C. ข้อความ** คำแทนจุดกลางและลูกศร 90 จุดต้องเลือกคำไทยต่อบริบท ผมเสนอ "และ" สำหรับรายการ, เว้นวรรคสองช่องสำหรับ metadata, "ดูรายการทั้งหมด" แทน "ดูรายการ" กับลูกศร

**T. ปุ่ม dock** ถ้ายอมให้ dock สูง 52 เป็น 56px ปุ่มจะได้ 46px โดยไม่ต้องใช้ pseudo element แต่ชีตจะเสียที่ 4px ผมแนะนำใช้ pseudo element แทน

**E. copy** ปุ่ม "ลองอีกครั้ง" ของ F1 ประเทศ และ skeleton ที่สูงเท่าของจริง ต้องการค่าความสูงจาก layout จริงของ KPI grid (วัดได้เมื่อมีจังหวัดที่มีข้อมูล F1)

```js
// app.js: เรียกจากปุ่ม .sheet-grip และจาก scroll ของ .panel-stage / .f2-stage
function setSheetExpanded(expanded) {
  document.body.classList.toggle("sheet-expanded", expanded);
  document.querySelectorAll(".sheet-grip").forEach((grip) => grip.setAttribute("aria-expanded", String(expanded)));
}
function watchSheetScroll(stage) {
  let last = 0;
  stage.addEventListener("scroll", () => {
    const top = stage.scrollTop;
    if (top > 40 && top > last) setSheetExpanded(true);
    else if (top <= 0) setSheetExpanded(false);
    last = top;
  }, { passive: true });
}
```
